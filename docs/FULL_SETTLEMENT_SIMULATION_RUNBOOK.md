# 一笔完整结算流程：原始模拟数据与操作手册

这是一组只用于 development/test 的模拟夹具，不是真实企业数据，也不构成生产结算或隐私计算能力证明。

## 文件

- 原始输入：[2026-08-full-settlement-simulation.json](../demo-data/2026-08-full-settlement-simulation.json)
- 核对答案：[2026-08-full-settlement-expected-result.json](../demo-data/2026-08-full-settlement-expected-result.json)

本组数据的交易批次是 `TB-2026-08-FLOW-001`，任务名称是“2026年8月可信结算全流程验收”。同一批次重复导入时，系统会复用已登记数据；如果想重新跑一遍，请把批次号和任务名称一起改成新的值。

## 先启动本地系统

在项目根目录执行：


这些账号只在本地 development/test 环境可用。

## 第一步：导入这组原始数据并启动首轮计算

当前系统的整包导入入口是测试环境专用接口，界面负责后续业务操作。登录交易中心后，在 PowerShell 执行下面的命令：

```powershell
$root = "D:\桌面\大创产品\hiddenchain-platform"
$login = Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:8000/api/auth/login" -ContentType "application/json" -Body (@{ username = "exchange"; password = "exchange123" } | ConvertTo-Json)
$headers = @{ Authorization = "Bearer $($login.access_token)" }
$fixture = Get-Content -Raw "$root\demo-data\2026-08-full-settlement-simulation.json"
$run = Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:8000/api/settlement/import-and-run" -Headers $headers -ContentType "application/json" -Body $fixture
$run | ConvertTo-Json -Depth 20
```

看到以下结果就说明首轮计算已完成：

- 任务状态：待主体确认；
- 计算作业：成功；
- 结果数量：1 条平台汇总结果 + 2 条主体结果；
- 隐私分析：成功；
- 原始记录接口返回：否；
- 页面上的可信执行链会显示数据授权、规则与计算、结果生成和审计待办。

如果 PowerShell 访问不了 8000 端口，说明后端还没有启动；先重新执行上面的本地启动脚本。

## 第二步：交易中心检查结果

1. 打开工作台，进入“结算任务”。
2. 找到“2026年8月可信结算全流程验收”。
3. 打开任务详情，查看“可信执行链”。
4. 进入“结算结果”，记录平台汇总结果和两条主体结果。
5. 不要在交易中心账号下确认主体结果；确认必须由发电企业和售电企业各自完成。

## 第三步：发电企业确认本方结果

1. 退出交易中心，登录 `generator / generator123`。
2. 进入“结算任务”，打开“2026年8月可信结算全流程验收”。
3. 点击“确认本方结果”或进入“结算结果”后点击本方结果的“签名确认”。
4. 审核金额为 **412300.00 元应收**、结算电量为 **1000.000 MWh**。
5. 意见填写“同意结算结果”，确认签名。

完成后，任务状态应变为“部分确认”。

## 第四步：监管方生成并批准审计报告

本组数据会因为演示环境没有配置跨域不出域远程证明而进入“中风险”，这是系统故意保留的审计关口，不是计算失败。

1. 退出发电企业，登录 `regulator / regulator123`。
2. 打开“审计与复核”，选择“2026年8月可信结算全流程验收”。
3. 查看事件时间线和证据辅助解释，至少检查：规则版本、证据一致性、原始数据边界、多方签名完整性。
4. 打开“审计报告”，找到本任务报告，点击“批准”。
5. 审核意见填写“已核对规则、授权、聚合结果和证据记录，批准本次结算报告”，确认批准。

批准后，报告状态应为“已批准”。

## 第五步：售电企业确认本方结果并闭环

1. 退出监管方，登录 `retailer / retailer123`。
2. 打开“结算任务”，进入“2026年8月可信结算全流程验收”。
3. 点击“确认本方结果”。
4. 审核金额为 **412300.00 元应付**、结算电量为 **1000.000 MWh**。
5. 意见填写“同意结算结果”，确认签名。

此时任务应进入“已审计归档”。回到任务详情，检查：

- 可信执行链全部完成；
- 双方结果均已确认；
- 审计报告已批准；
- 证据台账出现最终结果、结果确认和审计归档记录；
- 原始数据没有通过结果接口返回。

## 最终结算答案

系统固定规则为：

```text
应结金额 = 结算电量 × 合同单价
          - max(剩余偏差 - 偏差免罚阈值, 0) × 偏差罚金单价
          - 结算电量 × 服务费单价
```

代入本组数据：

| 项目 | 结果 |
| --- | ---: |
| 发电量 | 1250.000 MWh |
| 售电量 | 1000.000 MWh |
| 结算电量 | 1000.000 MWh |
| 原始偏差 | 250.000 MWh |
| 虚拟电厂调节 | 120.000 MWh |
| 调节后剩余偏差 | 130.000 MWh |
| 超出免罚阈值的偏差 | 30.000 MWh |
| 基础金额 | 420000.00 元 |
| 偏差罚金 | 4500.00 元 |
| 服务费 | 3200.00 元 |
| 最终应结金额 | **412300.00 元** |

因此：

- 齐鲁新能源发电有限公司：应收 **412300.00 元**；
- 海岱售电服务有限公司：应付 **412300.00 元**。

## 看到“不能确认”时怎么排查

| 页面提示 | 处理方式 |
| --- | --- |
| “任务不存在” | 检查当前登录环境和任务名称；重新导入后从任务中心打开最新任务。 |
| “等待监管批准” | 先切换监管方账号，在审计报告页面批准报告。 |
| “数据尚未准备好” | 说明导入没有成功；检查批次号、双方数据和启用规则。 |
| “跨域不出域证明未提供” | 这是本地演示环境的真实能力边界，不影响本组结算，但必须保留监管批准。 |
| 结果金额不一致 | 先核对批次是否是 `TB-2026-08-FLOW-001`，再按上面的公式核对。 |

Render 当前部署属于 review/test 评审环境，不是正式生产环境；本组文件建议在本地 development/test 环境使用。正式生产环境不会开放整包验收导入接口，避免把测试夹具当成生产数据。
