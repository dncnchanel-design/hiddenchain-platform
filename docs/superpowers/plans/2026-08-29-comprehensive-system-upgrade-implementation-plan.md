输出 `output/comprehensive-upgrade/baseline/` 下的脱敏报告；该目录不加入提交。

### 任务 0.2：运行基线

并行运行：

- 后端：`pytest -q`；

现有失败先归因到环境、用户改动或仓库基线，记录后再开始修复。

### 任务 0.3：建立机器可读矩阵

## 3. 阶段 1：权限、路由与生产安全

### 任务 1.1：生产秘密和构建上下文

涉及：`.gitignore`、`.dockerignore`、生产配置检查和对应测试。

- 在保留用户现有 `.gitignore` 修改的基础上补充 `.env.production`、密钥、运行数据库和已知本地工件。
- Docker 构建上下文排除生产环境文件、本地运行目录、测试数据库、截图和工具缓存。
- 固定 pnpm 版本，使 CI 与 Docker 一致。

验证：`git check-ignore`、Docker context/compose 配置测试、production build。

### 任务 1.2：生产路由 allowlist

涉及：`backend/app/main.py`、`backend/app/routers/prototype.py`、生产守卫脚本和 API 测试。

- 生产不注册 test-support、中央文件上传、篡改、恢复和无生产证明的 prototype 路由。
- demo/development 的兼容上传入口不声明 multipart 参数，直接返回 `410 Gone`。
- 生成生产 OpenAPI/实际路由清单并与显式 allowlist 比较。
- 所有仍保留的列表接口执行租户、个人授权和资源范围过滤。

### 任务 1.3：唯一能力契约

涉及：认证会话 DTO、后端 capability helper、`frontend/src/access.ts`、可信空间导航与按钮。

- 能力由角色上下文、组织、个人授权、资源范围和有效期共同产生。
- 前端移除重复的动作角色判断，消费服务端能力；后端仍重复校验。
- 冻结个人授权等价类：无授权、完整授权、单动作缺失、资源越界、已撤销、已过期。

### 任务 1.4：管理员兼容页面

涉及：system/overview/agents 前后端页面与路由。

- 新增或复用 admin-safe 摘要 DTO，仅返回服务健康、节点状态和脱敏技术指标。
- 修复页面加载必然 403；管理员不得得到目录、申请、任务、结果、业务审计或 Agent 正文。
- Reports/Anomalies 等敏感动作从能力契约决定，不能仅因 ADMIN 显示。

阶段门禁：路由 allowlist、双租户负向测试、管理员数据泄漏测试、前端路由/按钮组件测试全部通过。

## 4. 阶段 2：组织级连接器本地接入

### 任务 2.1：连接器身份与独立存储

涉及：`connector/app/main.py`、连接器配置、compose/render 配置和连接器测试。

- 每个逻辑连接器绑定唯一 `org_id × energy_domain`、`connector_id`、密钥和存储命名空间。
- 即使演示环境复用进程，也不得共享原始数据或签名身份。
- 修正并验证全部配置端点，重点复核 retailer/exchange URL。

### 任务 2.2：一次性上传凭证

在中央后端增加：

- 申请凭证接口；
- 可信连接器端点发现；
- 短期、单次、带 `jti` 的签名凭证；
- 主体、连接器、能源域、资源、格式、大小、目的和有效期绑定。

连接器增加：

- 受控 ingest 入口；
- 流式大小、schema、领域约束和 CORS 校验；
- nonce 原子消费与重放防护；
- 本地不可变版本保存。

### 任务 2.3：签名回执与中央登记

回执签名载荷包含设计规格要求的完整绑定字段。中央按 `(connector_id, receipt_id)` 幂等登记，只保存元数据、哈希和本地链位置。

支持上传成功但浏览器回调丢失后的回执查询与补登记。规范资源身份统一为 `(org_id, connector_id, energy_domain, resource_code, version)`。

### 任务 2.4：历史中央资产

- additive migration 增加来源、回执和能力状态字段；
- 历史资产只读回填为 `LEGACY_CENTRAL/BLOCKED`；
- 只读扫描运行数据库、对象/临时目录、日志与索引是否有原始载荷；
- 若发现载荷，切断平台访问并暂停此阶段完成，向用户请求处置决定。

### 任务 2.5：数据连接页面

- 五能源入口由服务端连接器目录生成；
- 浏览器持凭证直传对应连接器，中央不接收文件；
- 未配置、离线、无权限、校验失败和补登记都有真实状态；
- 删除手填错误资源代码，改为规范目录选择。

阶段门禁：所有验收主体的组织—能源域隔离、并发 nonce、跨连接器拒绝、canary 原始数据边界、五能源上传与目录登记测试通过。

## 5. 阶段 3：授权裁决与可恢复查询任务

### 任务 3.1：统一规则 schema

涉及现有 `DataUsageRequest`、策略服务、`local_data_boundary` 和可信查询路由。

- 策略中心能力并入数据授权。
- 规则统一匹配主体、规范资源、用途、动作、函数、时间、粒度、预算、版本和有效期。
- `ALLOW` 仅用于公开资源或提供企业有效站立授权；其他非公开数据走企业审批。
- 无匹配默认 `DENY`；跨主体请求拆成逐提供方子申请。

### 任务 3.2：授权快照与 TOCTOU 防护

- 确认生成绑定全部裁决维度的快照；
- 任务创建和连接器执行前重新检查撤销、过期、版本和预算；
- 新资源版本不继承旧授权，除非规则明确覆盖版本范围。

### 任务 3.3：持久化任务执行

- 正式 execute 立即返回任务 ID；
- 持久化 dispatch、lease、heartbeat、attempt 和结果引用；
- 租约过期可恢复，超过 attempt/有效期进入终态；
- 稳定任务幂等键透传连接器，响应丢失后对账而不重复计算。

### 任务 3.4：幂等和下载

- 幂等命名空间为 `(org_id, principal_id/client_id, operation, key)`；
- 命中旧操作只返回不透明引用并重新验权；
- 下载统一超时、401、错误清洗和取消；
- 离线交付重新校验当前授权，携带任务、授权、时间、哈希、签名并写审计。

阶段门禁：三类裁决、跨租户、规则撤销/过期、进程重启、响应丢失、并发执行与离线下载测试通过。

## 6. 阶段 4：审计、异常、通知、指标与兼容业务

### 任务 4.1：本地追加写入审计链

连接器对上传、规则复核、授权验证、计算和回执追加不可覆盖事件；中央保存签名摘要、链位置和验证结果。

### 任务 4.2：异常与 TTC

- 真实执行失败原子地产生异常事件；
- 异常处置通过 TTC 状态机和版本号推进；
- 删除直接回写任务状态的旁路；
- 并发处置仅一个成功。

### 任务 4.3：可靠通知

使用现有数据库实现 outbox/待发记录；业务变更与通知记录同事务提交，发送失败可重试、可观测、可审计。

### 任务 4.4：真实指标

从任务、授权、证据、异常和 `MetricRecord` 聚合，统一 DTO；包含统计窗口、截止时间、来源和新鲜度。未知或过期值返回 `null`。

### 任务 4.5：结算、交易与 Agent 兼容

- 结算/交易任务和结果映射至隐私计算；
- 合同与审批映射至数据授权；
- 凭证映射至审计追溯；
- 旧 URL 明确重定向且功能、参与方和可见范围不丢失；
- Agent 无审批消费者时只显示“生成待办/提交审批草案”。

阶段门禁：真实异常、TTC 并发、通知故障注入、指标契约、旧业务重定向和 Agent 文案测试通过。

## 7. 阶段 5：前端流畅性、排版与无障碍

### 任务 5.1：页面级拆包和错误恢复

- 可信空间页面改为 `React.lazy`；
- ECharts 使用 `echarts/core` 模块化引入；
- rejected preload 可重试；
- 增加应用与页面 ErrorBoundary；
- 冷启动 gzip JavaScript 每页硬预算 250 KiB。

### 任务 5.2：网络和轮询

- 长任务使用任务状态，不延长同步请求掩盖问题；
- TTC/MPC 轮询复用永久错误停机策略；
- Query/Agent 中文 IME 组合期间 Enter 不提交；
- 统一 blob 下载网络语义。

### 任务 5.3：定向 CSS 整理

- 合并 `trusted-energy.css` 中已确认互相覆盖的 shell/prototype 规则；
- 修复时间线空态逐字竖排、旧工作台操作列断字、顶栏长机构名、长哈希和菜单截断；
- 保持现有深蓝政企风格，不进行无关重绘。

### 任务 5.4：全站语义与视觉

- 每页一个 `h1`，无嵌套 `main`；
- 输入/筛选有可访问名称，图表有 aria 和文本摘要；
- 公共标题显示关键能力边界说明；
- 文本对比度 ≥ 4.5:1，触控目标 ≥ 40px，移动端优先 44px；
- 缺中文资源名时显示固定中文提示，不暴露英文资源代码。

阶段门禁：组件 DOM 测试及 390×844、1366×768、1440×900、125%–200% 缩放的浏览器视觉测试通过，无非 allowlist 元素相交、裁切或整页溢出。

## 8. 阶段 6：列表性能、CI 与部署契约

### 任务 6.1：服务端分页和 N+1

- 目录、计算、结果和审计在 SQL 层过滤/count/排序/limit；
- 唯一键稳定排序，最大 limit 100，非法参数 422；
- 批量/eager load 保持租户与个人授权范围；
- page size 20/100 时每请求 SQL ≤ 8，增量 ≤ 2。

### 任务 6.2：可复现性能门禁

使用设计规格固定的参考主机、容器配额、10k 夹具、预热、并发、样本和 nearest-rank 口径；非参考 CI 只报告时延，query-count/正确性硬门禁。

### 任务 6.3：浏览器回归进入 CI

- 为 Playwright 建立锁定依赖；
- 覆盖独特权限画像、每页状态、能源域入口、长文本、慢网、chunk 失败、会话失效和 IME；
- 路由/链接完整性检查禁止残留“策略中心”死引导。

### 任务 6.4：生产部署契约

- 平台签名密钥、数据库、身份配置缺失时启动失败；
- 外部策略适配器缺失时授权/执行 `BLOCKED`；
- 单个连接器缺失只阻断对应组织/能源域；
- 生产数据库只 migration，不加载演示种子；
- 静态资源验证压缩、不可变缓存与 ETag。
