# HiddenChain 全系统契约驱动升级设计

**日期：** 2026-08-29
**状态：** 用户已最终确认，进入实施
**适用范围：** `hiddenchain-platform` 的可信空间、兼容管理台、中央 FastAPI 服务、企业连接器、部署配置、自动化测试与视觉验收
**验收定位：** 公开演示端到端真实可用；生产模式严格 `fail-closed`；任何能力标签必须与实际证据一致

## 1. 背景与已确认决策

本设计基于对当前仓库的只读全量审计。审计确认，系统的问题不止是样式瑕疵，还包括前端入口与后端能力不一致、权限矩阵漂移、中央 CSV 上传违背数据边界、策略规则未参与真实查询裁决、连接器覆盖不完整、同步超时预算冲突、错误恢复不足，以及多处文字挤压和无障碍问题。

用户已确认以下决策：

1. 公开演示必须走完真实业务闭环，不允许用静态成功态、常量指标或不可达按钮冒充完成。
2. 生产环境不伪装尚未接入的外部基础设施；配置不足时必须阻断或显式标记 `BLOCKED`。
3. “可信空间七大模块”是唯一业务主入口；旧管理台只保留管理员和必要兼容功能。
4. 原始 CSV 不再进入中央后端，必须直接上传至相应企业连接器。
5. 采用“契约驱动升级”，保留现有可用代码，只重构已证实断链的边界，不整体重写，也不新增无必要的大型框架。

本设计延续 `2026-08-24-energy-subject-local-data-architecture-design.md` 中“中央控制平台 + 企业本地节点”的总体边界；出现冲突时，以本设计为准。特别是：没有明确匹配规则时默认拒绝；中央平台不得读取原始上传文件；可信空间业务导航固定为七个模块。

冲突与保留关系如下：

| 主题 | 2026-08-24 规格 | 本设计的处理 |
| --- | --- | --- |
| 无匹配规则 | 默认进入企业审批 | 默认 `DENY`；只有明确的审批规则才进入 `REQUIRE_APPROVAL` |
| 错误数据重传 | 新任务与旧任务不建立系统关联 | 资源可以形成不可变版本系列，但历史任务固定引用原版本，新版本不自动继承旧任务或授权 |
| 多主体申请 | 拆成提供企业子申请 | 继续保留；完整结果要求全部必要子申请批准，预先声明可部分交付时才允许标注缺失主体 |
| 主体本地审计 | 连接器保存完整本地记录 | 继续保留追加写入哈希链；中央只保存签名摘要、链位置和验证结果 |
| 结算与交易协同 | 必须保留 | 迁入七模块的信息架构，旧 URL 只做兼容重定向，不删除能力 |

## 2. 目标、非目标与原则

### 2.1 目标

- 建立唯一的页面、角色、动作和后端权限契约。
- 完成电、煤、热、气、油五个能源域的本地数据接入、目录登记、授权查询和签名证据闭环。
- 使授权规则真正参与查询确认和执行，且默认拒绝。
- 修复管理员、监管者和业务角色页面中可静态确定的 403、死入口、假动作和状态断链。
- 统一写操作的幂等、并发、任务状态、超时、错误恢复和审计语义。
- 降低可信空间首屏负担，消除短时断网或版本切换造成的白屏。
- 修复全站文字冲突、裁切、竖排、图文重叠、低对比度和无障碍问题。
- 将多角色、多能源域、多分辨率和生产边界检查变为可重复执行的放行门禁。

### 2.2 非目标

- 不把演示连接器描述成生产级 EDC、TEE、MPC 或区块链共识基础设施。
- 不证明企业上传前数据在现实世界中的真实性，只证明上传后的完整性、授权和计算过程。
- 不建设新的通用工作流平台、消息中间件或微前端框架。
- 不要求可信空间和旧管理台维护两套相同业务功能。
- 不覆盖、清理或回滚用户当前的未提交修改和未跟踪文件。

### 2.3 实施原则

- 后端是最终安全边界，前端隐藏不能代替授权。
- 原始数据始终留在企业连接器；中央只保存目录、授权、哈希、签名回执和审计摘要。
- 正式结果来自确定性执行路径；Agent 只能生成草案、解释结果和发起人工确认。
- 无明确允许即拒绝；无真实证据即不得标记 `REAL` 或 `LOCAL_REAL`。
- 优先复用 FastAPI、React、现有数据库和任务模型，以最小改动形成完整闭环。

## 3. 目标架构

```text
可信空间 Web
  │
  ├─ 读取中央目录、权限、授权、任务、证据和聚合指标
  │
  └─ 持一次性上传凭证，直接上传原始文件
                      │
                      ▼
中央控制平台 ───── 企业连接器（电 / 煤 / 热 / 气 / 油）
  │                   │
  │ 签发上传凭证       ├─ 本地校验、版本化和保存原始数据
  │ 验证连接器回执     ├─ 本地规则复核与确定性计算
  │ 保存元数据/授权    └─ 返回签名目录、聚合结果和证据
  │ 维护任务/审计
  └─ 永不读取或保存原始 CSV
```

中央平台负责身份、组织、能力契约、目录索引、授权、任务编排、证据验证、审计和对外展示。连接器负责原始数据、本地目录、版本、规则复核、确定性计算和签名。

本地与演示环境可以用独立容器和独立数据库模拟企业节点；生产环境的连接器端点、公钥和允许来源必须由部署方显式配置。缺少配置不得回退到中央模拟数据。

## 4. 唯一能力与权限契约

### 4.1 契约结构

登录会话或专用能力接口返回以下事实：

- 当前主体、组织、能源域、角色上下文、个人授权及其有效期；
- 可访问的业务模块；
- 每个资源允许的动作，例如 `view`、`upload`、`request`、`approve`、`execute`、`verify`；
- 动作当前状态及阻断原因；
- 能力标签及其证据引用；
- 可用连接器和资源目录版本。

前端路由、菜单、按钮和动作状态只消费该契约，不再维护独立角色矩阵。后端每个动作仍执行相同的权限和租户校验，不能信任前端传入的能力声明。

角色只提供组织和业务上下文，不直接授予动作。最终能力必须由个人授权、组织、资源范围和有效期共同派生；同一角色的两个账号可以具有不同能力，且授权撤销后立即失效。

### 4.2 标签语义

- `REAL`：已接入目标生产实现，并能提供对应证据。
- `LOCAL_REAL`：在主体本地连接器中真实保存或确定性执行，但不宣称外部生产基础设施已接入。
- `ADAPTER`：协议和调用边界真实，外部实现由适配器替代。
- `DEMO`：仅演示环境存在，生产环境不注册或不可调用。
- `BLOCKED`：配置、授权、节点或依赖不足，系统明确阻断。

标签由后端根据运行环境、节点能力、签名验证和配置状态产生。前端只展示，不自行推断。

### 4.3 兼容管理台

可信空间固定保留七个业务模块：运行总览、智能数据查询、数据目录、数据连接、数据授权、审计追溯、隐私计算。主体中心作为独立身份入口存在，不加入七模块业务导航。

旧管理台不再承担重复业务流程，只保留管理员需要的系统、节点、Agent 运维和兼容入口。管理员页面使用专门的脱敏摘要 DTO，不调用只允许业务角色的接口；DTO 只能包含服务健康、节点状态和脱敏技术指标，不得包含目录、申请、任务、结果、业务审计、Agent 提示或响应正文。旧业务 URL 可以在过渡期重定向到可信空间对应页面，并记录弃用信息。

现有结算/交易任务和受控结果迁入“隐私计算”，数据合同、授权申请与审批迁入“数据授权”，凭证和交易审计迁入“审计追溯”。迁移改变的是信息架构，不删除原有结算与交易协同能力。

## 5. 企业连接器本地接入协议

### 5.1 上传凭证

“覆盖五个能源域”不表示只有五个共享连接器实例。每个逻辑连接器身份只能绑定一个 `org_id × energy_domain` 信任边界；演示环境即使复用进程，也必须使用独立存储、独立密钥和独立连接器身份，禁止同能源域内多个组织共享数据仓库。

中央平台在确认当前用户具有本组织数据管理权限后，签发一次性上传凭证。凭证至少绑定：

- `jti`、`org_id`、`connector_id`、主体节点和能源域；
- 规范化 `resource_code` 与允许的数据格式；
- 最大文件大小、签发时间、过期时间；
- 唯一随机数和上传目的；
- 允许的连接器端点或连接器标识。

凭证短时有效且只能使用一次。连接器验证中央签名、主体、资源范围、过期时间和随机数，拒绝跨主体、跨能源域或重放上传。

### 5.2 浏览器直传

上传流程如下：

1. 前端从中央申请凭证和目标连接器地址。
2. 浏览器把文件直接提交至企业连接器的受控接入端点。
3. 连接器在本地完成格式、表头、类型、行数、大小和领域约束校验。
4. 连接器生成不可覆盖的新资源版本，保存本地文件或结构化记录，并计算内容哈希。
5. 连接器返回签名回执；签名载荷至少包含 `receipt_id`、凭证 `jti`、`org_id`、`connector_id`、`energy_domain`、`resource_code`、版本、schema 哈希、内容哈希、行数、时间和签名 `kid`，不包含原始行。
6. 浏览器把签名回执提交中央登记；中央验证连接器签名和凭证关联后，登记目录、能力标签和审计事件。

凭证消费、本地版本提交和回执生成必须在连接器本地原子完成。中央以 `(connector_id, receipt_id)` 幂等登记；上传成功但浏览器回调丢失时，持原凭证身份可以从连接器查询同一回执并重试登记。

连接器需配置明确的 CORS/允许来源，并只接受带有效凭证的写请求。生产环境不得使用通配来源。中央原有 CSV 上传路由必须删除 `UploadFile`/multipart 参数和所有 request-body 解析路径；开发兼容入口在路由入口直接返回 `410 Gone`，生产环境完全不注册，确保不会先把文件读入内存、临时文件、日志或追踪系统。

历史中央上传产生的资产先做只读清点和来源回填，统一标记为 `LEGACY_CENTRAL/BLOCKED`，不得参与 `REAL`、`LOCAL_REAL` 查询或执行。若确认中央仍保留历史原始载荷，立即禁用所有平台读取路径并将其登记为发布阻断项；迁移到企业连接器、删除或转为离线受监管归档必须取得用户另行授权。在处置完成前不得宣布全面升级完成。

### 5.3 五能源统一协议

电、煤、热、气、油使用相同的健康、目录、接入、计算和证据协议；领域差异通过资源 schema 和函数能力表达。前端资源选择来自连接器目录，不再要求用户手填与查询解析器不一致的代码。

每个资源区分稳定的 `resource_code` 和可本地化的显示名称。规范资源身份是 `(org_id, connector_id, energy_domain, resource_code, version)`；查询解析、授权规则、执行和回执验证不得只依赖裸 `resource_code`。

版本属于同一资源系列，但每个版本内容不可覆盖，历史任务固定引用原版本。新版本不得自动继承旧版本授权，除非提供企业签发的规则明确覆盖相应版本范围。

## 6. 授权与查询执行

### 6.1 统一策略入口

当前不可达的策略中心并入“数据授权”。规则至少包含主体、资源、用途、动作、函数、时间范围、输出粒度、预算、版本和生效状态。

裁决结果只有三类：

- `ALLOW`：资源公开，或提供企业已经签发且仍有效的站立授权明确覆盖本次请求；
- `REQUIRE_APPROVAL`：非公开数据存在明确的企业审批规则，生成提供方子申请；
- `DENY`：明确拒绝，或没有任何适用规则。

任何非公开数据都必须具有提供企业已签发的有效批准；监管者没有免审批通道。没有匹配规则时必须 `DENY`，不能隐式转成审批，也不能由已有但不相关的授权绕过。跨主体请求按提供企业拆成子申请；完整结果只有在全部必要子申请批准后发布，只有请求预先声明允许部分结果时才可发布并醒目标注缺失主体。规则版本、裁决输入和命中原因进入审计证据。

确认结果生成绑定主体、资源、用途、动作、函数、输出粒度、预算、规则或审批版本及有效期的授权快照。正式执行时必须重新校验该快照仍然有效，并重新检查撤销、过期、主体变化和更高优先级拒绝；确认后规则被撤销、过期或修改时，旧确认不得继续执行。

### 6.2 查询状态机

查询主流程固定为：

```text
解析意图 → 匹配规范资源 → 获取能力与授权裁决 → 人工确认
        → 创建幂等执行任务 → 连接器本地计算 → 验证签名结果
        → 发布聚合结果和证据
```

正式函数只能来自平台与连接器共享的确定性 allowlist，例如求和、平均值、最大/最小值、计数、中位数、增长率、同比/环比、分组汇总、阈值判断、趋势、PSI 和受控 MPC 聚合；未知函数直接拒绝。中央发送带任务号、授权快照、时间戳、随机数和预算的签名执行信封，连接器校验签名、防重放和预算后才计算，并对结果和本地链位置签名。

确认接口只做快速、无副作用的解析和裁决。任务创建和连接器执行前都必须重新校验提供企业授权版本、撤销、过期和预算。正式执行创建任务并立即返回任务 ID；前端按退避策略查询任务状态，或复用仓库已有的安全事件机制。潜在 20–60 秒的连接器或模型调用不得阻塞在前端统一 15 秒请求中。

正式任务至少包含 `PENDING`、`RUNNING`、`SUCCEEDED`、`FAILED`、`BLOCKED`、`EXPIRED` 等明确终态。前端对 401、403、404 等永久错误停止轮询，对短暂网络错误显示可恢复状态并有限重试。

任务的 dispatch、lease、heartbeat、attempt 和结果引用持久化在数据库中。执行器以租约领取任务，进程重启或租约过期后由恢复器重新领取；超过最大 attempt 或业务有效期的任务进入明确终态。中央把稳定的任务幂等键透传给连接器，连接器持久化该键与结果，因此响应丢失或中央重试只能取回同一底层计算结果，不能再次执行。中央恢复后还需用任务 ID 与连接器对账，处理“连接器已完成、中央未收到响应”的状态。

### 6.3 幂等与并发

上传登记、查询执行、授权决定、异常处置和演示审计动作统一使用：

- 幂等键；
- 规范化请求指纹；
- 已保存响应或任务引用；
- 明确的过期和冲突语义。

幂等唯一键使用 `(org_id, principal_id/client_id, operation, idempotency_key)` 命名空间；请求指纹包含资源身份、版本、授权版本和用途。相同键和相同指纹只返回不透明任务/操作引用，并重新执行当前租户、个人授权和结果可见性检查；绝不跨租户或在权限已撤销后回放缓存业务结果。相同键和不同指纹返回冲突。状态变更使用现有版本号或 `If-Match` 语义，避免双击、超时重试和并发审批产生重复版本或非法状态。

### 6.4 结果发布与离线下载

在线页面只展示受控结果。离线结果下载必须在全部必要提供方批准完成且当前交付授权仍未撤销、未过期时开放；任务曾经成功不构成永久下载权。

下载接口每次重新校验个人权限、授权范围、版本和可见性。交付包至少携带任务编号、提供方授权范围与版本、生成时间、结果哈希、连接器签名和中央验证记录，并追加下载审计事件。

## 7. 审计、异常、通知与指标

### 7.1 审计和演示边界

审计追溯展示授权版本、上传回执、执行请求、连接器签名、结果哈希和验证状态。查询与验证按个人授权、主体、任务和资源范围过滤，不能只按角色过滤。

上传、规则复核、授权证明校验、确定性计算和回执生成都必须在企业连接器本地追加不可覆盖的审计事件并形成哈希链。中央只保存签名摘要、链位置和验证结果，不保存连接器本地完整业务载荷。

篡改和恢复只属于 `DEMO`：仅演示环境注册，只允许监管角色，并明确记录模拟事件。生产环境的 OpenAPI 和路由表中不得出现这些动作。

生产检查覆盖整个 prototype/test-support 路由面，而不只检查篡改和恢复。每个仍保留的原型路由必须有明确生产用途、角色、租户范围和能力标签证明；否则生产环境不注册。

### 7.2 异常与 TTC 状态机

连接器失败、签名验证失败、证据死信和正式任务异常应原子地产生异常事件。异常处置只记录决定，再通过唯一合法的 TTC 状态迁移推进任务；不得直接回写任务状态、风险级别和阶段。

迁移必须校验当前 attempt、状态版本和允许的下一状态，并保留完整历史。并发处置只有一个能成功。

### 7.3 通知可靠性

在不引入消息中间件的前提下，使用现有数据库建立持久化待发记录或 outbox。业务状态与待发记录在同一事务中提交；发送失败保留重试状态、错误摘要、指标和审计信息，不能静默返回零。

### 7.4 真实指标

运行总览和指标页从任务、授权、证据、异常及现有 `MetricRecord` 聚合。指标 DTO 使用统一字段名，并包含统计窗口、数据截止时间、来源标签和新鲜度状态；无法计算或已经过期的值返回 `null` 并附原因，不得用 `0`、空数组或常量冒充当前测量结果。

## 8. 页面与交互设计

### 8.1 七模块职责

- **运行总览：** 真实节点、任务、授权、证据和异常聚合；无数据时展示明确空态。
- **智能数据查询：** 展示解析、资源、裁决、确认、执行、证据的完整状态链。
- **数据目录：** 展示连接器签名上报的资源、版本、主体、能力和可用状态。
- **数据连接：** 展示五能源连接器健康、目录和本地上传；未配置时显示 `BLOCKED` 原因。
- **数据授权：** 统一规则、申请、审批、撤销和历史版本。
- **审计追溯：** 展示证据链、回执和验证结果；按环境显示演示能力。
- **隐私计算：** 统一 TTC/MPC 任务状态、终态、轮询和失败恢复。

Agent 写操作在存在真实审批消费者前只能表述为“生成待办”或“提交审批草案”，不能称为“执行计划”。

结算/交易任务及受控结果在“隐私计算”延续，数据合同与审批在“数据授权”延续，相关凭证在“审计追溯”延续。旧页面重定向后，原参与方、状态、结果范围和审计可见性不得丢失。

### 8.2 视觉和排版修复

保持现有深蓝政企视觉方向，不进行无关品牌重绘。对已出现实际回归的重复 CSS 做定向合并，避免继续依赖源码顺序覆盖。

最低要求：

- 390×844、1366×768、1440×900 下无整页横向溢出；表格只在自身容器滚动。
- 修复时间线空态逐字竖排、旧工作台操作链接断字、顶栏长机构名碰撞和用户菜单不可恢复截断。
- 文本不得与图标、按钮、边框或相邻列重叠；状态、空态和错误文案不得被固定高度裁切。
- 长 DID、哈希、任务号和资源版本保持视觉省略，但提供键盘可达的复制或完整查看入口。
- 资源缺少中文名称时显示“未命名数据资源，请由提供企业补充中文名称”，不得回退暴露英文 `resource_code`。
- 高频交互命中区至少 40px，移动端优先 44px。
- 普通文本与背景对比度至少 4.5:1；不能只用颜色表达状态。

### 8.3 语义和无障碍

- 每页一个明确 `h1`，避免嵌套 `main`。
- 输入和筛选具有持久标签或可访问名称。
- 地图和图表启用 ECharts aria，并提供数据摘要或等价文本。
- 公共标题组件必须渲染调用方传入的能力边界说明。
- 中文输入法组合期间按 Enter 不得误提交。
- 焦点状态、键盘导航、对话框和标签页语义保持可用。

## 9. 流畅性、加载与错误恢复

### 9.1 页面级拆包

可信空间壳层只同步加载布局和当前页面。七模块及独立主体中心按页面 `lazy` 加载；工作台 ECharts 使用 `echarts/core` 的模块化范式。不得为此新增图表库。

懒加载 Promise 在失败后允许重新尝试，应用和页面层提供错误边界。发布切包或短时断网时显示可恢复错误，不出现必须手动清缓存的永久白屏。

### 9.2 统一网络契约

- 普通查询使用统一短请求预算。
- 长执行创建异步任务，不通过不断延长浏览器超时解决。
- 下载复用统一 API 层的超时、401 事件、错误清洗、追踪信息和取消能力。
- 轮询复用共享的永久错误停机规则，并采用退避和可见性控制。

### 9.3 静态资源和构建

静态资源启用压缩、内容哈希和长期不可变缓存；HTML 保持可重新验证。固定 Node/pnpm 契约，使 CI、根 Dockerfile 和前端 Dockerfile 使用一致版本。

可信空间首次进入某一页面的脚本压缩初始硬预算为 250 KiB。口径为清空缓存后首次进入该页面实际传输的全部 gzip JavaScript 之和，包含共享 vendor 和当前页面 chunk，不计 source map。超限必须由用户批准书面例外，不能仅提供分析后自动放行。

### 9.4 服务端列表性能

目录、计算任务、结果和审计列表必须在数据库层完成个人授权/租户过滤、条件过滤、计数、稳定排序和 `limit/offset`，不得先 `.all()` 再由 Python 切片。排序使用唯一键兜底，服务端 `limit` 最大为 100，非法分页参数返回 422。详情关联使用批量查询或适当的 eager load，消除逐行查询主体、版本、证据和参与方的 N+1 路径；关联预加载仍必须遵守相同租户和证据范围。

使用可重复生成的较大数据夹具记录 SQL query count 和 p95/p99；优化前后必须保持分页总数、排序、可见范围和空页语义一致。

## 10. 生产安全与部署

- `.env.production`、本地密钥、数据库、运行产物和浏览器工件必须同时排除于 Git 与 Docker 构建上下文。
- 生产配置明确列出全部连接器端点、公钥、平台签名密钥、允许来源和超时。
- 启动或健康检查验证端点与服务名一致；不能只检查部分连接器。
- 生产环境不注册测试支持、原型篡改、恢复或其他演示写路由。
- 平台签名密钥、生产数据库和身份安全配置缺失时服务启动失败。生产外部策略适配器缺失时，授权确认和执行统一 `BLOCKED`，不得回退到演示裁决器；单个可选连接器缺失只阻断对应组织/能源域。
- 生产数据库只执行 schema migration，不加载演示组织、种子目录、任务或结果。
- 生产镜像逐步拆分运行时与开发依赖；任何科学计算依赖删除前必须先确认实际适配器使用情况和构建收益。

## 11. 迁移顺序

### 阶段 1：基线与保护

- 记录当前 Git 状态、构建产物和既有测试结果。
- 明确用户已有修改的文件边界，不覆盖或重排无关内容。
- 建立当前路由、角色、动作和接口的事实矩阵。
- 建立缺陷账本：P0 表示数据/安全边界破坏或核心闭环完全不可用，P1 表示主要角色、页面或场景失败，P2 表示有明确绕行方式的质量、性能或维护性问题。
- 只读清点历史中央上传资产和可能的原始载荷位置，设计 additive schema、来源回填和回滚脚本；此阶段不删除历史数据。
- 一旦发现历史原始载荷，先使平台代码和运行服务不可读取，再暂停相关发布并请求用户选择迁移、删除或离线归档；未经授权不执行破坏性处置。

### 阶段 2：能力契约与安全边界

- 后端形成唯一能力 DTO，并让可信空间消费。
- 对齐管理员摘要接口和兼容入口。
- 对演示路由、租户范围、生产配置和密钥忽略做首轮加固。

### 阶段 3：五能源本地接入

- 定义并实现上传凭证、连接器接入、签名回执和中央登记。
- 统一五能源目录和资源代码。
- 以可回滚的 additive migration 增加资产来源和连接器回执字段，回填历史资产为 `LEGACY_CENTRAL/BLOCKED`。
- 新直传路径验证通过后，把中央 CSV 读取路由切换为 `410 Gone` 迁移响应；切换前后验证目录和审计兼容，回滚只恢复路由版本，不把历史资产提升为真实能力。

### 阶段 4：业务闭环

- 统一授权规则和查询裁决。
- 改造持久化 dispatch/lease/attempt、连接器幂等对账、异常、TTC 状态迁移、通知和真实指标。
- 修复管理员及兼容页面的权限断链。

### 阶段 5：前端流畅性与视觉

- 完成页级拆包、错误边界、网络契约和下载统一。
- 合并已证实冲突的 CSS，逐页修复排版、响应式和无障碍问题。

### 阶段 6：全量验收

- 执行单元、契约、集成、端到端、视觉、性能和生产边界检查。
- 修复所有 P0/P1；P2 延期必须记录复现、影响、负责人、目标版本，并取得用户明确批准，不能仅凭书面说明自动放行。
- 形成可复现的验收报告、截图和能力矩阵。

每一阶段遵守 Build → Test → Review，上一阶段未通过不得将其标记完成。

长任务期间，每个阶段同步维护 `docs/backend-implementation/05_PROGRESS.md`、`09_WORKSTREAMS.md` 和 `10_RELEASE_SYNC.md`，记录范围、证据、测试结果、遗留风险和 Build → Test → Review 结论。

## 12. 测试与放行门禁

### 12.1 契约与权限

自动生成或校验“页面—动作—角色上下文—个人授权—接口—真实副作用—能力标签”矩阵。测试必须证明：

- 所有显示的动作都有真实成功、明确拒绝或明确阻断结果；
- 前端无入口的敏感 API 仍受后端保护；
- 管理员、监管者和各业务角色不会因权限矩阵漂移导致整页失败；
- `ALLOW`、`REQUIRE_APPROVAL`、`DENY` 三类裁决分别生效，且没有匹配规则时默认拒绝；
- 非公开数据的 `ALLOW` 必须能追溯到提供企业仍有效的站立授权；否则必须走提供方审批，监管者也不例外；
- 主体、资源、用途、动作、函数、时间、输出粒度、预算和规则版本任一不匹配均不能越权；
- 确认后规则撤销、过期、修改或主体变化会使执行重新裁决并拒绝旧快照；
- 双租户 canary 证明所有目录、策略、任务和证据列表均按租户隔离；
- 生产 OpenAPI 和实际路由表与显式 allowlist 一致，所有 prototype/test-support 路由要么未注册，要么逐项具有生产用途、角色、租户范围和标签证明。
- 多主体请求逐提供方审批；完整结果缺少任一必要批准时不可发布，允许部分交付的请求必须标注缺失主体。
- 管理员接口与页面不返回目录、申请、任务、结果、业务审计或 Agent 正文。
- 新资源版本不会自动继承旧版本授权，除非规则明确覆盖相应版本范围；历史任务始终引用原版本。

验收主体表至少包含发电、售电、煤、热、气、油企业，电、煤、热、气、油五个交易中心组织，监管者和管理员。个人授权冻结为有限等价类：无授权、完整授权、单动作缺失、资源越界、已撤销、已过期；主体、资源、用途等单变量负向用例逐项覆盖，其余维度使用 pairwise。能力清单中的每个动作至少有一次成功和一次拒绝。浏览器测试覆盖每个不同能力画像，不能只按相同 `role_code` 抽一个账号。

### 12.2 五能源闭环

电、煤、热、气、油分别完成：

1. 申请一次性凭证；
2. 原始文件直传本地连接器；
3. 中央验证签名回执并登记目录；
4. 以公开资源、有效站立授权或提供企业审批发起查询；
5. 完成本地计算并验证签名证据；
6. 证明中央数据库、日志和响应中不存在原始行。

还需覆盖过期凭证、重放、跨主体凭证、错误 schema、离线节点、签名错误和重复回执。

同一凭证被并发使用时只能有一次成功；回执中的 `connector_id`、`resource_code`、`org_id`、版本和哈希必须与凭证及本地记录逐项绑定。客户端不得替换服务端可信配置给出的目标端点。允许与拒绝 Origin、预检、流式大小上限、中断上传和回执错配都必须有负向测试。

对全部配置的“组织—能源域”连接器断言 `connector_id`、密钥指纹和存储命名空间互不混用；同能源域不同组织之间以及不同能源域之间，目录、回执、原始存储和计算结果的跨连接器读取都必须拒绝。

“中央不存在原始行”的证明限定在本系统可控边界：中央 API schema 不接受文件字段；使用唯一 canary 行完成直传后，检查中央数据库、中央对象/临时目录、应用日志和中央响应均不存在该 canary，而连接器本地存储存在。交付说明明确不涵盖部署方不可见的外部代理和历史备份。

兼容中央上传入口测试直接发送带 canary 的 multipart body，断言开发环境在解析请求体前返回 `410 Gone`、无临时文件和日志载荷，生产环境路由不存在。连接器本地测试还要证明上传、授权校验、计算和回执事件只能追加，并能从回执链位置验证哈希链连续性。

### 12.3 状态、幂等与故障恢复

- 相同幂等键和相同请求只产生一个版本、任务或决定。
- 相同键不同请求产生冲突。
- 并发审批和异常处置只有一个合法状态迁移成功。
- 连接器超时后前端不会重复创建任务；恢复后可以继续查询原任务。
- 在任务 `RUNNING` 时终止并重启执行进程，租约回收后原任务必须继续并进入终态。
- 模拟“连接器完成但响应丢失”后重试，断言连接器只执行一次，中央通过同一任务幂等键取回结果并完成对账。
- 通知失败有持久记录、可重试且可观测。
- 401、403、404 停止轮询；临时网络失败有限退避。
- 离线下载在授权有效时生成带任务、授权、时间、哈希和签名的交付包并写入审计；授权撤销或过期后，即使任务曾成功也必须拒绝再次下载。

### 12.4 浏览器与视觉

锁定 Chromium、Playwright、中文字体、`zh-CN` locale、`Asia/Shanghai` timezone 和 DPR。缩放使用实际 Chromium 页面缩放而不是只改变 DPR，并记录有效 CSS viewport。锁定依赖并进入 CI，至少覆盖：

- 390×844、1366×768、1440×900；
- 125%–200% 字体缩放；
- 所有可信空间模块、主体中心和保留的管理员页面；
- 全部目标角色；
- 整页溢出、文字裁切、元素相交、控制台错误、失败 chunk、慢网、会话失效；
- 中文输入法 Enter 场景。
- 资源缺少中文名称时的固定中文提示，且页面不暴露英文资源代码。

测试夹具覆盖正常、空态、错误和最大长度文本。弹窗、菜单、徽标等合法叠层进入显式 allowlist，其他元素相交和文字裁切视为失败。API/组件层执行全能力矩阵；浏览器视觉按“每个页面状态 + 每个独特权限画像 + 每个能源域入口”覆盖，避免维护无意义的重复截图。

机械检测后必须人工复核关键截图，尤其是顶栏、侧栏、表格、对话框、图表、空态和长文本。

同时增加组件级 DOM 测试，覆盖能力契约驱动的菜单和按钮、加载/错误/空态、可访问名称、标题地标、长文本入口和永久错误停止轮询。现有纯函数及 API 测试不能替代组件渲染测试。

组件测试必须覆盖同角色不同个人授权组合、授权撤销和过期，证明页面动作不由岗位名称固定决定。

增加路由与链接完整性测试：遍历菜单、卡片、CTA 和帮助文案中的内部目标，断言目标可达或存在明确重定向；仓库和运行界面不得再把用户引向已并入“数据授权”的策略中心。

旧结算、交易、合同、结果和凭证 URL 的回归测试必须证明重定向后原功能、参与方范围、任务状态、结果范围和审计可见性仍然保留。

### 12.5 构建、性能与生产检查

- 前端 lint、类型检查、单元测试和生产构建通过。
- 后端单元、契约、集成和属性测试通过。
- 指定发布参考主机并在发布记录中固定 OS、CPU 型号、Docker 版本和应用镜像 SHA；容器限制为 2 vCPU/4 GiB，使用仓库固定的 SQLite 配置与 10,000 条目录、任务和审计夹具，先预热 20 次，再以并发 10 各执行 200 次，按 nearest-rank 计算百分位。仅在同一参考主机上硬门禁：普通列表/详情 p95 不高于 500ms、p99 不高于 1,000ms，任务创建 p95 不高于 750ms、p99 不高于 1,500ms；其他 CI runner 只报告时延，query count 和正确性仍为硬门禁。
- 目录、计算、结果和审计列表在 page size 20 与 100 时每次请求最多 8 条 SQL，二者 query-count 增量不超过 2；不得随单页记录数线性增长。
- 在禁用缓存、排除 source map 的条件下，记录每个可信空间页面冷启动时实际传输的全部 gzip JavaScript，包括共享 vendor 和当前页 chunk；每页总量不高于 250 KiB。超限只能由用户批准的书面例外放行，不能仅提供分析后自动通过。
- 使用脱敏配置执行生产 compose/config 检查，验证全部连接器和密钥契约。
- 生产负向启动测试证明平台签名密钥、数据库或身份安全配置缺失时启动失败；外部策略适配器缺失时授权/执行为 `BLOCKED`；单个连接器缺失只阻断对应组织/能源域；干净数据库只执行 migration 且不生成演示数据。
- 验证静态资源的 `Content-Encoding`、`Cache-Control`、`ETag` 或等价缓存行为。

## 13. 风险与回退

- **直传网络限制：** 浏览器到企业内网连接器可能受到 CORS 或私有网络策略影响。连接器必须提供明确允许来源和可诊断健康状态；生产端点由企业部署方配置。
- **兼容数据：** 现有中央上传产生的目录统一标记 `LEGACY_CENTRAL/BLOCKED`，不能冒充连接器本地版本。只有重新完成本地接入和签名登记后才能升级能力。若存在历史原始载荷，必须先切断平台访问并阻断发布；迁移、删除或离线归档需另行取得用户授权。
- **异步任务迁移：** 旧同步调用可以在兼容期包装为任务，但不能让一次重试创建多个底层执行。
- **CSS 合并回归：** 只合并已确认重叠或冲突的选择器，每批均做桌面和移动截图对比，不进行全文件无证据重写。
- **重型依赖拆分：** 先测量镜像、启动和实际 import，再拆 runtime/dev 依赖，避免误删适配器能力。

如某阶段出现不可接受回归，应回退该阶段的独立改动，而不是回滚用户原有修改或清空工作区。

## 14. 完成定义

只有同时满足以下条件，才能称为“全面升级完成”：

1. 七大业务模块和保留的管理员页面都通过角色上下文、个人授权与动作矩阵。
2. 所有验收主体的“组织—能源域”连接器身份、密钥和存储隔离通过，且五能源本地接入、授权查询和签名证据全链路通过。
3. 当前运行中的中央平台数据库、对象/临时目录、日志、索引和 API 不含企业原始记录；所有新上传均不经过中央。经用户明确批准保留的离线历史备份必须单独登记，且不得挂载或供平台访问。
4. 权限、策略、幂等、状态机、异常、通知、离线交付和指标均有可重复测试证据。
5. 生产环境严格关闭演示能力，未配置能力被真实阻断。
6. 目标视口和字体缩放下无文字冲突、溢出、图文交叠或整页横向滚动。
7. 关键页面无不可恢复白屏，长任务无超时诱发的重复操作。
8. 所有既定构建、测试、浏览器、安全和生产检查通过。
9. 交付物包含实现说明、能力矩阵、测试报告、性能数据和视觉截图。
10. 既有结算与交易协同能力已迁入七模块并通过功能保留回归；连接器本地追加写入审计链可由中央摘要验证。
