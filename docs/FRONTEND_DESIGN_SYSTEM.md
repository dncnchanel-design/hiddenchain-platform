# 隐链明算前端设计系统

本规范用于后续新增页面和现有页面迭代。目标是维持政企级 B2B 平台的秩序感、可读性和可审计性，不为单页引入独立视觉语言。

## 设计原则

- 以业务任务、授权边界、执行状态和审计证据为信息主线。
- 白色/浅灰内容区为主，深蓝仅用于导航、品牌和高权重信息；红色只用于风险、失败和危险操作。
- 优先使用页面内容区、表格和分组标题，只有在确实需要分组时使用 Surface 容器。
- 不使用大面积渐变、发光、粒子、玻璃拟态、营销横幅或装饰性科技纹理。
- 所有真实业务 ID、哈希、凭证编号使用等宽字体；不得用虚构字段填充接口没有提供的数据。

## Tokens

Token 集中定义在 `frontend/src/styles.css` 的 `:root`：

- 品牌：`--brand-900`、`--brand-700`、`--brand-50`
- 文本：`--ink`、`--text-secondary`、`--text-muted`、`--text-disabled`
- 状态：`--success`、`--warning`、`--danger` 及对应浅色背景
- 间距：`--space-1` 至 `--space-9`，以 4px 为基准，常用页面间距为 8/12/16/24/32px
- 圆角：控件 4px、内容容器 6px、弹层 8px
- 字体：`--font-body`、`--font-mono`；正文 14px，辅助信息 11–13px，页面标题 24px
- 层级：`--z-sidebar`、`--z-topbar`、`--z-drawer`、`--z-modal`、`--z-toast`
- 动效：`--motion-fast` 用于按钮/状态反馈，`--motion-normal` 用于抽屉等布局变化；不使用持续发光动画

## 基础组件

优先复用 `frontend/src/components/ui.tsx`：

- `PageHeader`：页面眉题、标题、业务说明、右侧操作
- `Surface`：内容区标题、说明、操作和正文容器
- `Button`：主操作、次操作、危险操作、幽灵操作；异步操作必须使用 `busy`
- `DataTable`：统一表头、横向滚动、空状态；长 ID 使用 `CodeValue`
- `StatusTag`：所有状态使用标准成功/警告/危险/中性色，不直接写独立颜色
- `Field`、`Modal`、`Notice`、`LoadingState`、`ErrorState`、`EmptyState`：统一表单、反馈和无数据表达

交互要求：可聚焦控件必须保留 `:focus-visible`；异步按钮显示加载态；危险操作使用确认或明确的危险按钮；弹窗支持遮罩点击关闭和 `Escape` 关闭。

## 页面模板

- 工作台：`PageHeader` → 工作空间/策略摘要 → 核心指标 → 待处理任务 → 近期调用 → 状态/告警
- 列表页：`PageHeader` → 筛选/分段控件 → `Surface` + `DataTable` → 分页或空状态
- 详情页：`PageHeader` → 任务摘要 → 分区信息 → 操作反馈 → 审计/凭证引用
- 表单页/弹窗：`Field` + 原生控件 → 清晰校验提示 → 取消/主操作；不能提交时禁用主操作
- 审计页：对象筛选 → 时间线/证据列表 → 状态核验 → 受控检索或确认动作
- 配置页：分段标签 → 当前配置摘要 → 可编辑区域 → 保存反馈和生效范围

## 提交前自查

1. 页面是否使用现有 Shell、PageHeader、Surface 和状态组件。
2. 是否保留真实 API 字段语义、权限判断和路由，不新增虚构业务数据。
3. 是否覆盖加载中、错误、空数据、成功和危险操作反馈。
4. 1366/1440/1920 宽度及移动端是否没有全页横向溢出；表格可在自身容器内横向滚动。
5. 是否通过 `pnpm exec tsc -b`、`pnpm build`，并完成真实登录后的关键路由冒烟检查。
