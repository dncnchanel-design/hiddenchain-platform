# 可信执行模型与能力边界

## 当前执行事实

| 维度 | 当前实现 | 可作的声明 |
| --- | --- | --- |
| 计算运行时 | `LOCAL_CONTROLLED_SETTLEMENT_V1` | 应用进程内确定性结算 |
| 算法 | `CONTROLLED_SETTLEMENT_V1` | 按已签规则包计算与舍入 |
| 执行环境 | `APPLICATION_PROCESS` | 无硬件隔离证明 |
| 远程证明 | `NOT_PROVIDED` | 不得声明 TEE |
| 证据后端 | `LOCAL_EVIDENCE_LEDGER_V1` | 数据库哈希台账，可做摘要一致性核验 |
| 区块链交易 | 未配置 | 不得声明“已上链”或共识确认 |
| API 原始记录 | `false` | 当前 API 响应不返回 Vault 原始记录 |
| 跨域不出域证明 | `false/NOT_PROVIDED` | 不得由 API 最小披露推断跨主体不出域 |
| OPA | production 必须远程服务 | PDP 不可用时 fail-closed |

## 本地受控结算

适配器从本机 Vault 读取参与方测试/接入数据，执行确定性规则、场景派生和电网约束校核，只把汇总结果、输入承诺、输出哈希和执行回执写入业务数据库。该边界可复算、可测试，但不是密码学多方计算。

## 受控数据使用入口

前端 `/trusted-execution` 将“如何使用数据”作为一条可操作的请求链：身份核验 → 自然语言意图解析 → 五类策略裁决（禁止、延迟、汇总、仅计算、直接受控提供）→ 执行路由 → 结果审查 → 证据台账。请求中的粒度（月份、日、15 分钟、明细）和空间范围（区域、组织、计量点）会进入策略上下文，不能只依赖页面上的“汇总”选项。

策略动作与当前实现的映射如下：

| 策略动作 | 当前实际方式 | 当前状态 | 生产能力边界 |
| --- | --- | --- | --- |
| `ALLOW` | `DIRECT_CONTROLLED_API` | 本地适配器可用 | 仍受字段和身份范围约束 |
| `DELAY` | `DELAYED_CONTROLLED_RELEASE` | 本地适配器可用 | 只表示时间窗口，不等于脱敏 |
| `AGGREGATE` | `LOCAL_CONTROLLED_AGGREGATION` | 本地适配器可用 | 结果为聚合，不证明跨域不出域 |
| `COMPUTE_ONLY` | `LOCAL_CONTROLLED_COMPUTE` | 仅测试适配器 | PSI/MPC 或 TEE 尚未接入，不能声明密码学隔离 |
| `PROHIBIT` | `BLOCKED` | 不执行 | 拒绝结果写入审计链路 |

细粒度跨主体请求会展示候选 PSI/MPC、TEE 机密计算等方案，但候选方案不是实际执行方式；当前回执明确保留 `TEST_FIXTURE_ONLY` 和 `cross_domain_non_export_verified: false`。这样既把赛题要求的策略闭环落到系统里，也避免把调研中“可选技术路线”误写成已经部署的能力。

## 证据台账

每条记录包含业务对象、载荷摘要、顺序号、记录摘要、后端代码和状态。核验会重新计算摘要并比较。它能发现数据库载荷与记录摘要不一致，但不提供分布式共识、不可篡改硬件或公链/联盟链确认。

历史模型和表名 `BlockchainEvidence` / `blockchain_evidence` 为数据库兼容而保留，不是能力声明。

## 外部候选方案

策略目录可返回 PSI/MPC、TEE、秘密共享、同态加密、联邦学习等候选方案；受控数据使用入口会把其中与当前请求相关的候选方案带入执行回执，但统一标记：

```json
{
  "implementation_status": "NOT_CONFIGURED",
  "execution_capability": false,
  "requires_external_runtime": true
}
```

当前作业仍由本地适配器执行；候选方案不得出现在“实际执行方式”字段。

## 升级为可声明能力的最低条件

- MPC：至少两个独立主体节点、协议实现、密钥/份额管理、失败与串谋模型、可复现实验和安全评审。
- TEE：受支持硬件、可信镜像度量、远程证明验证、证书链、重放防护和密钥释放策略。
- 区块链：明确网络、节点与治理、合约、交易回执、确认策略和链故障处理。
- 跨域不出域：独立连接器/网关、数据面监测、传输与出站控制、日志及第三方可核验证明。

接入前，产品验收结论对这些能力必须为 `NO`。
