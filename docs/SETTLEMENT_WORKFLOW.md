# 结算任务工作流

## 状态模型

| 状态 | 含义 | 下一步 |
| --- | --- | --- |
| `DRAFT` | 任务已创建，可能仍有前置阻塞 | 补数据/签名/规则/授权 |
| `READY` | 严格预检通过 | 交易中心启动结算 |
| `RUNNING` | 正在执行 | 等待回执；重复启动被拒绝 |
| `PENDING_CONFIRMATION` | 已生成双方结果 | 发电、售电分别确认 |
| `PARTIALLY_CONFIRMED` | 一方已确认 | 另一方确认 |
| `AUDITED` | 双方已确认并记录完成证据 | 监管复核/归档 |
| `EXCEPTION` | 执行或证据异常 | 复核原因后重新准备 |

## 五步创建

1. 基本信息：任务名、交易批次、结算周期和业务说明。
2. 参与方：恰好一个发电主体和一个售电主体。
3. 数据就绪：检查匹配批次的数据引用、质量和承诺签名；不足可继续保存。
4. 规则与计算：选择启用规则；执行方式固定为本地受控结算。
5. 复核提交：展示全部事实、能力边界和阻塞项后创建任务。

创建与启动分离。创建接口允许记录待准备任务；启动接口重新查询数据库并执行严格预检，不能依赖前端判断。

## 八步可信链

1. 任务创建
2. 主体确认
3. 数据就绪
4. 规则授权
5. 受控计算
6. 结果生成
7. 双边确认
8. 审计完成

任务详情从真实参与方、上传、协议、计算作业、结果、签名、证据和异常推导每一步状态。链路不是静态进度动画。

## 关联规则

以下页面接受 `?task_id=<id>` 并提供返回任务入口：可信数据目录、结算规则、隐私计算、结算结果、证据台账、审计复核、审计报告和风险处置。所有关联查询仍受角色和组织范围限制。

## 双边确认

- 发电/售电只能确认 `org_id` 等于本人组织的 `ORG` 结果。
- 交易中心、监管和管理员不能代确认。
- 首方确认进入 `PARTIALLY_CONFIRMED`；双方均确认进入 `AUDITED`。
- 重复确认幂等，不生成重复签名。
- 最终完成时写入 `RESULT_CONFIRMATION` 本地证据台账记录。
