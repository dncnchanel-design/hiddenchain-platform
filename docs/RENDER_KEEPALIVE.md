# Render 比赛期间保活

此工具是公开演示环境的临时预热措施，不能保证服务始终在线。它不处理业务数据，只访问平台和七个演示连接器的健康检查地址。定时任务运行在 GitHub，不需要本机保持开机。

## 安装状态

仅在本地存在脚本和工作流时，不会自动生效。GitHub 定时任务只运行默认分支上的工作流；需要先将相关文件安全发布到该仓库的默认分支。仓库的 Render 服务监听 `main`，更新该分支可能触发 Render 重新部署，进而丢失免费实例本地文件；发布前必须确认当前线上数据备份和部署行为，不能直接覆盖线上业务数据。

默认不设置变量，定时任务不会访问 Render。工作流不会自动创建或开启保活窗口。

## 开启与关闭

开启前，在 Render 的 Billing 页面确认本月剩余额度：8 个实例连续运行 48 小时约需 384 实例小时，72 小时约需 576 小时；还要预留原有用量、其他服务和停止请求后到休眠的时间。超过额度，工作区的免费 Web 服务会被暂停到下月。

在 GitHub 仓库的 **Settings → Secrets and variables → Actions → Variables** 新建或修改仓库变量 `RENDER_KEEPALIVE_WINDOW`。它的值使用两个 UTC 时间，中间用斜线分隔，例如：

```text
2026-12-01T00:00:00Z/2026-12-04T00:00:00Z
```

这是北京时间 2026 年 12 月 1 日 08:00 到 12 月 4 日 08:00。请根据比赛时间修改；结束时间必须晚于开始时间，窗口最多 72 小时。启用后可在仓库 **Actions → Render competition keep-alive → Run workflow** 手动执行一次，尽快唤醒服务；之后由计划任务约每 5 分钟运行。首次唤醒仍需等待。

提前关闭：删除或清空该仓库变量。已排队或已经启动的单次检查仍可能继续；如需立即停止，可同时在 Actions 中取消相关排队或运行中的任务。关闭不会立刻关闭 Render 服务；没有其他访问时它们之后会正常休眠。到结束时间后，脚本会自动停止发请求，即使忘记删除变量也是如此。建议赛后删除变量，避免无意义的定时检查。

## 限制和检查

- 计划任务可能延迟或被丢弃，GitHub 工作流也可能被禁用；Render 仍可能重启或发生故障，无法承诺零冷启动。比赛前应手动运行并检查 Actions 中最近一次结果及每个服务的状态。
- 当前仓库为公开仓库；标准 GitHub 托管运行器的公开仓库用量目前免费，但请在仓库或计划变化时重新核对 [GitHub 计费说明](https://docs.github.com/en/actions/concepts/billing-and-usage)。
- 保活不改变 Render 的临时文件存储规则；服务重启、休眠或部署时本地 SQLite 和其他本地文件可能丢失，需要另行备份。不要把此方案当作生产环境的数据保障。
- 变更 Render 域名或连接器数量后，要同步更新脚本中的健康检查地址。
